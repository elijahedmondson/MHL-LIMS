## 1. Dilutions that Excel had turned into times

Excel reads a dilution such as `1:100` as a time of day (1 hour and 100 minutes) and stores it as a fraction of a day, `0.111111111`. 379 dilutions were stored this way. Each was converted back with 1:N = (value × 24 − 1) × 60, and every one came out as a whole number, which suggests the conversion is right. Dilutions with text after them (for example `1:50 ON4C` or `1:100 60'`) were not affected. The recovered dilutions carry **no incubation time**, while most typed ones do; please check a few against the protocol binder and confirm whether a default time applies.

## 7. Other gaps

- Protocols with no species: 13.
- Protocols with no antigen retrieval: 1.
- The export has no assay ID, no active/retired status and no date last validated. The pilot gives each entry a number (#1, #2, ...) in export order; the real database ID should replace it when the database itself is migrated.
- A few control-tissue entries name the person whose blocks are used as controls. That is fine internally, but worth knowing if the catalog is ever shown to investigators.

## What each flag in the pilot means

- **dilution-recovered**: Excel had stored this dilution as a time of day. It was converted back; please confirm it against the protocol.
- **name-recovered**: Excel had turned this antibody name into a date. It was restored; please confirm.
- **duplicate**: An exact copy of another entry. Hidden from the request form.
- **species-blank**: No species recorded.
- **species-unrecognized**: Part of the species text was not recognized.
- **double-incomplete**: Marked as a double stain, but only one protocol follows the marker.
- **double-same**: A double stain that lists the same protocol twice.
- **retrieval-blank**: No antigen retrieval recorded.
